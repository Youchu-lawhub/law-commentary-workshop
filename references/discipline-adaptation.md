# 部门法与规范类型适配

入口可为任何条文，但须识别法域、版本、位阶、效力、部门法及具体规范功能。混合条文逐款拆解；跨部门法争点检查每个相关框架。下表是研究路由，不是强制目录或法律结论。

| 对象 | 主要问题 | 常见误用 |
|---|---|---|
| 民商法给付或责任规则 | 请求权、主体、要件、抗辩、效果、竞合、证明 | 把内部外部关系或不同责任基础混为一谈 |
| 原则/一般条款 | 具体化路径、与具体规则关系、适用次序、裁量边界、可审查理由 | 用价值口号直接推出裁判结果 |
| 定义条款 | 概念的外延与边界、类型、跨条文作用、拟制和排除、解释后果 | 强套请求权要件目录 |
| 授权/组织规范 | 权限主体、来源、对象、条件、程序、限制、监督和救济 | 从权限存在推导行为当然合法 |
| 刑事实体规范 | 保护法益、罪刑法定约束、构成、违法与责任、主观要素、未遂与共犯、竞合、量刑 | 以民法利益衡量跨越不利类推边界 |
| 行政规范 | 权限、程序、羁束/裁量、比例与平等、审查标准、效力及救济 | 将私法意思自治当作行政权力依据 |
| 诉讼/证据规范 | 程序阶段、诉讼角色、启动条件、期限、证明、制裁、程序救济 | 只写实体权利不写程序后果 |
| 宪法规范 | 权利或国家组织功能、基本权利限制、规范具体化、审查机制与可诉性 | 把应然解释写成已存在的诉讼渠道 |
| 国际法/外国法 | 法源结构、语言、制度语境、管辖及适用范围、原文核对 | 用中国法的规范层级和审计字段冒充当地核验 |

原有案例矩阵中的“法院/裁判”等栏目不适用时，以授权决定、审查决定或实际相关的适用材料补充说明，不虚构案例来填满模板。没有案例不自动说明无法成文，也不能宣称实务检索已充分。

现有初始化、来源状态和放行脚本主要围绕中国法字段；其他法域可复用证据追踪思想，但需先调整项目画像和核验标准并验证工具，否则只能报告人工审查结果，不能把中国法脚本的通过视为当地法研究完整。历史条文则锁定所研究版本和当时法源，不适用“必须现行有效”的标签。

复杂部门法问题如缺乏相应原始材料或语言能力，应说明具体缺口，定向补资料或收窄范围。不要仅写“公法加比例原则”便声称已完成方法适配。
