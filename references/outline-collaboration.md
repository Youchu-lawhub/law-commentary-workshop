# 大纲共创与调试

大纲是论文的论证程序，不是章节名称清单。目标不是让用户从一份机器生成的大纲中被动挑错，而是让 Agent 提供可比较方案、揭示取舍，再与用户逐轮收敛。正文写作必须等待大纲闸 `G3_outline` 明确批准。

## 一、准备设计简报

先从规范档案、资料简报、案例矩阵和命题—证据矩阵提炼：

- 一个核心问题和一句可被反驳的研究主线；
- 需要证明研究主线的三至七个子命题；
- 最强反方、决定性反例和仍有条件的结论；
- 每个子命题已有的主要来源 ID 与证据缺口；
- 目标读者、目标字数和期刊体例。

若这些条件尚不具备，退回相应阶段，不用空标题掩盖研究缺口。

## 二、提出真正不同的候选架构

有实质结构取舍时给出两至三个架构；用户已有合适结构时直接细化，不为了凑数制造同义变体。可考虑：

- 问题—回应型：以一个解释难题展开，适合研究主线鲜明的期刊论文；
- 要件—效果型：按适用范围、要件、效果、竞合和证明展开，适合规范密度较高的私法条款；
- 案例类型型：从裁判冲突或事实类型反推解释规则，适合实践分歧明显的条款；
- 规范史—体系重构型：修法或规范冲突是核心时使用。

每个候选只先展示：叙事主线、三级以内标题、每部分功能、优点、风险、预计篇幅。Agent 应明确推荐一个方案并说明理由；用户可选择、混合或提出新方案。

## 三、制作章节论证卡

用户选择方向后，为每一节写“论证卡”：

```text
章节：三、……
本节问题：
本节结论：
论证前提：
关键规范/案例/文献 ID：
最强反方：
回应方式：
与上一节的承接：
对下一节的必要性：
预计字数：
```

标题必须表达本节承担的论证功能。仅有“概述”“问题”“完善建议”等泛化标题时，继续追问其具体命题。

## 四、五轮压力测试

1. 覆盖测试：核心争点、要件、效果、竞合、程序/证明和重要反方是否都有归属；哪些材料没有进入任何章节，为什么。
2. 顺序测试：任一章节的结论是否依赖尚未证明的后文；删除或交换章节后论证是否受损。
3. 边界测试：文章是否悄悄更换研究对象、扩大到无法支撑的制度论，或把立法论混入解释论。
4. 反方测试：最强反方是否在最有利位置被完整重构；决定性案例能否推翻当前结构。
5. 篇幅测试：各部分字数是否匹配贡献，背景和比较法是否挤压中国法核心论证。

把结果写入 `06a-outline-brief.md` 的覆盖矩阵：`核心命题 → 所在章节 → 证据 ID → 反方 → 预计字数 → 状态`。存在孤立命题、重复章节或无证据的归属性命题时，不提交定稿。

## 五、与用户逐轮收敛

每一轮只处理会改变结构的少量决定：

1. 第一轮确认叙事架构与研究主线；
2. 第二轮确认章节边界、先后顺序和应删除内容；
3. 第三轮确认重点篇幅、最强反方与知识增量；
4. 必要时再迭代，不设机械轮数。

每轮先给修改建议和原因，再问用户选择。用户意见进入 `10-decision-log.md`；修改后的大纲提高版本号，并列出“本版相对上版的变化”。不要在用户尚未定纲时偷偷开始正文。

## 六、定稿标准

只有同时满足下列条件，才请求用户批准 `G3_outline`：

- 研究主线可由章节链条完整推出；
- 每一章都有不可替代的功能，兄弟标题分类标准一致；
- 主要材料和反方均有归属，证据缺口已补齐或明确限缩；
- 比较法服务具体中国法问题；
- 摘要预期结论、导论承诺与结语能够相互对应；
- 总字数与各章预算符合目标期刊；
- 用户已理解并认可研究范围、结构和关键取舍；不要求复述测试。

最终确认问题应具体：

> 是否批准 `06-outline.md` 当前版本作为正文写作的结构基线？批准后我将按该结构写作；任何实质改变仍会记录并在初稿闸再次请您确认。

完整条文评注采用条文覆盖链与关键争点链，不能把全部问题强归入单一命题。不同结构方案只在有真实取舍时提出；用户已有明确合适结构时直接细化。
